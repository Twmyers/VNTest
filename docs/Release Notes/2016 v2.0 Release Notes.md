

# 2016 v2.0 Release Notes

## Upgrade Changes

- **If you upgrade to the 64-bit version of
  Value
  Navigator and are using a ..udl or a ..vnudl to connect to a
  data provider (e.g. a PPDM hub, or a database with capital actuals),
  you will need to change the name of the provider from MSDORA.1 to
  Devart.Data.Oracle. Just open the .udl/.vnudl in a text editor such as
  Notepad, and replace the “Provider” in the file.**
- Previous 6.x versions allowed duplicate costs to be created on a well.
  To guarantee accurate reporting, we force unique names in
  Value
  Navigator 2016 onwards. When upgrading from 6.x to 2016 v2,
  duplicate operating or capital costs will have a number appended to
  their names to make them unique.

## Features

### Technical Comparison Tab

**New:** A new tab under the Comparison tab for technical data.

The Technical tab allows users to view technical volumes by Reserves
Plans or Reserves Categories, set a row as baseline for variances, and
generate reports.

Results can be viewed for single entities (wells and groups), folders,
and rollups.



### Type Well Enhancements

**New:** Advanced options when creating or modifying type wells.

**New:** P10/P90 ratio has been added to the Cross Plots tab
distribution summary area.

We have incorporated new methods for creating more representative type
wells. You can use the original type well method or now create type
wells that are associated with a specified probability (i.e. P10, P50,
P90). Or, choose your own custom weighting factors.

We added a graph to the Type Well options dialogue which displays a
Probability Plot of EUR. This shows how the expected EUR is derived. You
enter a well count and select a weighting method, which determines
future drill program EUR’s. The new distribution line reflects the well
count and method, and we also display the original distribution.



To view the new Weighting Factor options:

1.  Select an existing Type Well from the Type Wells view or,
2.  Create a new Type Well from selected wells in the entity explorer or
    the Cross Plots tab
3.  Open the Options dialogue (the gear icon in the Type Well Definition
    tab)
4.  Select the Factor Type or open the Advanced Options to see all
    additional selections



Factor Type:

- Choose from Unfactored, Percentile or P-Mean, or Custom Factors.
- The Percentile method also requires a percentile value. P10, P50, and
  P90 are provided by default, but any percent value can be entered.

Advanced Options:

Both Aggregation and Selected Well methods use Monte Carlo to determine
the reserves that are associated with the desired probability
(Percentile or P-Mean).

- Choose a weighting factor method
  - Aggregation – Determine weighting factors that achieve the reserves
    associated with the probability
  - Selected Well – Choose whole wells whose average approximates the
    reserves
- Enter a future drill count.
  - A drill count \&gt; 1 results in a new probability distribution
- Choose the number of points to use when extrapolating the high and low
  ends of the distribution lines
- Choose how trend lines are calculated. Use smoothed data or actual
  points.

For more information, refer to Society of Petroleum Engineers:
SPE-175967 – Creating More Representative Type Wells

**New:** ‘Copy To…’ a new Type Well

This button lets users make a copy of the selected type well that uses a
different percentile. This way users can easily create related P10, P50,
and P90 type wells.



## Additions to Data Views

### Display all grouped entities in grids

**New:** ‘Include child entities’ option in Layout panel.

When this option is selected users will see both parent and child
entities for the current hierarchy selection in the grid. This makes it
simpler to compare child well inputs in multiple groups.

**New:** New Entity Type and Root Group columns in the Well Info and
Custom Fields area

These appear at the bottom of the Values list by default and can be
repositioned by dragging them in the list. Grouped wells will display
the root group they belong to. The root group is the highest level group
in a nested set.



### Data Areas for Volumetric Inputs

**New:** Data Views areas for Oil, Gas, and CBM Volumetric data. The old
Oil Vol. and Gas Vol. tabs have been removed from under the Well Views
tab.

Default tabs have been added under the Predictions Data tab. These areas
can also be found in the Volumetric section in the areas list when
adding a new top or side tab.

When editing inputs in the grid, where the forecast has a hard link to
the volumetric solution, the forecast should be updated to reflect the
new remaining reserve in place. If the new calculated value is less than
the start of the last segment, break the link. (same rules as editing a
linked forecast from the Volumetric tab).

- The Data Layout Panel on the right of the Data View gives users the
  power to customize the way the data is displayed in the tabs.
- To inspect a well’s inputs that you see on the Data View, right-click
  the entity and choose ‘Go to Volumetric Tab’. This will show you the
  input data you are viewing, on the selected entity, in the Entity
  View.
- Export the data in the tab to Excel by clicking ![](../Images/2016-v2.0-Release-Notes-6.png) at the
  top of the tab.
- Select one or more entities in the Data View, right click and choose
  Select Entities on Entity Explorer to quickly find those wells in the
  explorer.



### Data Areas for Allowances

**New:** Data Views areas for Allowances – General, and Allowances -
Monthly.

These new areas are found in the Allowances section in the list when
adding a new top or side tab.

Default tabs have been added under the Interests & CDN Royalties Data
tab. These areas can also be found in the Allowances section in the
areas list when adding a new top or side tab.

- The Data Layout Panel on the right of the Data View gives users the
  power to customize the way the data is displayed in the tabs.
- To inspect a well’s inputs that you see on the Data View, right-click
  the entity and choose ‘Go to Allowances Tab’. This will show you the
  input data you are viewing, on the selected entity, in the Entity
  View.
- Export the data in the tab to Excel by clicking ![](../Images/2016-v2.0-Release-Notes-8.png) at the
  top of the tab.
- Select one or more entities in the Data View, right click and choose
  Select **Entities on Entity Explorer** to quickly find those wells in
  the explorer.

### Extended behaviour of overlapping production history option to all data

**Moved:** The ‘Use overlapping production history instead of forecast’
option has been moved to Project Options \&gt; General from Project Options
\&gt; Economics.

History is prioritized over forecast when the option is selected in all
areas of the application, not just economics. This includes:

- Wellhead
- Plant (excluded - Plant tab will always use overrides if they exist)
- Type Wells
- Cross plots
- Group/Rollup calculation

### New Interest Reversion Types

We added new interest reversion types for added flexibility, primarily
for interests in the U.S.

**New:** Interest Properties \&gt; Reversion Type

- BOE Volume – a volume reversion calculated as gross BOE including any
  custom products that are flagged as 'Include in volume equivalence
  calculation'
- BTCF – a cash reversion based on gross profit after net profits
  interests are paid
- BCTF before NPI – a cash reversion based on gross profit before net
  profits interests are paid
- Net Operating Income – a cash reversion based on net revenue after
  severance tax, operating costs, and net profits interests are paid
- Net Rev before NPI less Severance – a cash reversion based on net
  revenue after severance tax, but before operating costs and net
  profits interest are paid

### Display sparse data in multi-entity reports (added in Value Navigator 2016)

**New:** Show Uneconomic Entities option in Hierarchy Table Properties
in Report Designer.

We can now show empty rows in multi-entity reports for entities that
don’t have results. This allows users to see which wells in a selection
are uneconomic.

### Display sparse data in single-entity reports

**New:** Show Empty Dates option in Report Properties in Report
Designer.

We can now show empty rows in monthly table reports for dates that don’t
have results. This allows users to see all dates in a series and make
spreadsheet exports consistent.

Combined History and Forecast queries in Custom Reports

Three new queries have been added to Custom Reports. These queries
return data for input and wedge ResCats (PNP, PUD etc.).

**New:** Report query called History and Forecast to Economic Limit

This query combines production history with forecast gross values to the
economic limit for the current entity, plan, and scenario. The query
only reports values for wells whose economic values have been
calculated.

**New:** Report query called History and Resolved Technical Forecast

This query Combines production history with resolved technical forecast
production for the currently selected entity and plan. Technical
forecasts are now returned from lower ResCats similar to economic fall
back. (I.e. the PDP forecast is returned if queried from TP, and PD and
TP do not have their own forecast). This allows users to get total
forecast numbers at folder levels where not every forecast is in the
same ResCat.

**New:** Report query called Resolved Technical Volumes

This query returns the resolved technical cumulative, remaining, and
ultimate volumes at the Reference Date for the currently selected entity
and plan. forecasts are resolved, so unlike other technical reports,
results can fall back to other ResCats. For example, if a well only has
a PDP forecast, then that forecast will be displayed at PDP, PD, TP,
etc.

### Resolved Technical Reserves Added to Report Designer

**New:** The Report Designer now supports technical volumes fields. The
fields are listed in the Technical Volumes folder in the Toolbox.

For each product, plus All Oil, All Gas, Liquids Total (BOE):

- Gross cumulative, remaining, and ultimate volumes
- WI, RI, Co. Share, and net remaining volumes
- estimated WI, RI, Co. Share, and net cumulative and ultimate volumes.
  The estimated share is taken from the first step after the calculation
  date
- Gas products also have raw versions of all these columns

### Project Security Policies

**New:** Import from External Source policy.

We now provide the ability for administrators to grant permission on the
Update from External Source menu item without being able to import other
data in other Import functions. The existing "Import" policy will
continue to allow user to import from all locations.

**New:** Export policy

This policy allows access to the Export dialogue to export data to an
XML or vndb file.

**New:** Create Entities policy

This policy gives permission for a user to create new entities. Editing
permission will still be taken into account.

**New:** Delete Entities policy

This policy gives permission for a user to delete entities which they
have permission to edit.

**Modified:** Edit Entity, Write to Pending, Write to Accepted

These security policies are modified so that users who do not have
security rights on Pending or Accepted can no longer create or edit
Change Record values in those statuses. Users now require ‘Write to
Pending/Accepted’ policies to modify those records.

### Alberta Modernized Royalty Framework (MRF)

In order to avoid schema changes in 2016 and previous versions, new data
fields required for MRF calculations were added to those versions as
custom fields. These are now incorporated into the schema in 2016 v2:

- Total Measured Depth
- True Vertical Depth (Average)
- True Vertical Depth (Max)
- Total Lateral Length
- Completion Type
- Acid Concentration
- Acid Fracture Volume
- Ring Fence Calculation ID

**New:** Calculated TVDavg and TVDmax are loaded based on well license
when updating production from IHS and GeoLogic in ‘Update from External
Source’

### Allow negative values in Daily Data

**Modified:** The ability to have negative volumes in the Daily Data
tab.

Users can now reconcile field estimates with measured reported volumes
by adjusting daily data. There is no change to monthly data, negative
values are not supported.

### Allow PPDM import to delete existing values

**New:** ‘Remove production history when absent from data source or file
import’ under User Options \&gt; Import Parameters.

This option allows for the deletion of existing database values when the
import source has nulls, so that production data (i.e. field values) can
be reconciled with reported volumes.

### NavPort (.vna) Data File Source

We now support NavPort as a vendor for .vna data files
(www.navport.com).

- "Navport" appears in vendor list (Administration \&gt; Vendor IDs \&gt; Show
  Vendors)
- Added to Products dialogue \&gt; Import Codes
- "Navport" added as a value on Data Views \&gt; Wells and General
  Economics (Data Source)

### Other

**Modified:** There is an improved Report Designer version of the
Royalty by Product – Detail report. This has been converted from the
Custom Reports version.

**Improved:** Upgrades are faster to VN 2016 v2 from the same source

## Bug Fixes

### Technical

- Fixed a decline issue where O+W with Oil and 1+WOR where the O+W is
  lower than Oil would decline to zero and then start up again in
  subsequent time steps. The O+W forecast was not properly flagged as
  having negative volume.
- Fixed an issue in Draw Decline where the Start Date was set earlier
  than expected. If production history exists, a new segment will be set
  to the first month after history. Start Date on existing segments will
  not change.
- Fixed an issue where ratio forecasts were being created each time new
  wells were generated via import. Now, we will only recalculate ratios
  if the User Option “Recalculate ratios on import” is checked.
- Fixed an issue where a negative input on the Plant tab - Gas Analysis
  would cause an error. The Plant tab - Gas Analysis now considers
  negative numbers as invalid input and reverts to previous values.
- Fixed an issue where the Master Gas Analysis did not recalculate after
  the last contributing gas analysis was deleted.
- Fixed an issue where the P/z fit line plotted horizontally when the
  abandonment pressure equals zero.
- Fixed graph behavior to display all data points in history regardless
  of the zoom setting. It was possible to miss a meaningful spike in the
  data at certain zoom levels.
- Fixed the auto fit point display on graphs so that the points are not
  displayed if the decline is not active.
- Log/Time graphs could trim data at the start of a forecast if the
  initial rate was very high compared to subsequent dates (i.e. exponent
  \&gt; 1.5). Changed graph scale logic to display all forecast data.
- Resolved an issue where Type Wells were not created with expected
  volumes when child wells have predictions that overlap history. Now
  that the project option is applied in all areas of the application the
  issue is resolved. See ‘Extended behaviour of overlapping production
  history option to all data’ in Other Enhancements.
- Fixed an issue when a segment start date was the same as the end date
  resulting in a product segment with zero volume. This could occur if
  the forecast start date was set during an import. We now handle these
  zero volumes when other products cause the forecast to continue.
- Fixed an issue in Spreadsheet Import where secant decline factors (Di)
  were imported as tangent.
- Fixed an issue where users could not create a rollup that included
  wells they could not edit, only those they had View permission for.
  Creation of rollups is now allowed with entities for which the user
  only has ‘View’ permission.
- Fixed an issue where users could not always select the first point for
  profile drawing. Added profile point dragging to more easily mark
  endpoints.

### Economic

- Fixed the inflation calculation to consistently return
  beginning-of-step inflated values. We now consistently show the value
  as of the beginning of a step, not the end. This applies to all cases
  that use inflation.
- Sliding Scale Royalties were not considering well count. Fixed an
  issue where sliding scale (payable and receivable) was not calculated
  per well.
- Fixed an issue where a well would return before payout results for one
  month before reverting to a new interest. This could occur for wells
  with no capital included in the calculation, but having a payout
  reversion type. With the fix, these wells will now immediately revert
  on the first step.
- Fixed an issue for BC wells where changing from Crown to Freehold
  interest caused the well to return an uneconomic result.
- Fixed an issue for Saskatchewan Fourth Tier Gas where the royalty
  trigger ratio value was not exactly matching the expected value of
  3500 m3/m3. It was triggered at ~3480 m3/m3.
- Fixed an issue for Ontario wells where the royalty calculation
  returned the error ‘The calculation has failed. See the log file for
  details.’ This would happen for wells with a secondary product
  forecast (i.e. oil wells with a gas decline or gas wells with an oil
  decline).
- We now consider the T&T cost royalty deduction when calculating
  royalty receivable for freehold interests. Fixed an issue where the
  royalty deduction for a T&T cost was not applied as expected.
- Fixed an issue where mineral tax was treated in the same way as a
  royalty, reducing net revenue and net volume. It is now treated in the
  same way as a severance tax which does not affect net volume.
- Fixed an issue where the Allowances tab could be blank if the well did
  not have any selections for Royalty Calculation and Before Tax
  Calculation on the Interests and Royalties tab.
- Fixed an issue where the Economics \&gt; General tab option ‘Do not apply
  for uneconomic developed cases’ was not working as expected and
  abandonment was applied. If a well had no production or costs between
  the calculation date and the reference date it was not being processed
  by the option check.
- Fixed an issue where Economics \&gt; General ‘Delayed Abandonment’ was
  ignored when a case resulted in a single monthly result (post economic
  limit calculation) at the same date as the Reference Date.
- Fixed an issue where a change in a Fiscal Regime was not recognized as
  a trigger to recalculate entity results. This would happen if a user
  changed a variable’s value, then clicked ‘Save’ before ‘OK’. Selecting
  OK on its own would cause a recalculation.

### Reporting

- Addressed an issue where folder or container results are always
  recalculated even though the results should be up to date. This can
  occur if an entity lower in the hierarchy has a result timestamp in
  the future. In this case
  Value
  Navigator always flags the folder as needing recalculated. We
  now check timestamps when a database is opened and display a message
  when the condition is detected. This could be caused by running
  Value
  Navigator on a computer that has an incorrect date setting.
- Fixed a report issue where payout appeared to occur at the wrong date.
  The Project Setting ‘Last year for monthly output’ could result in a
  delay in the after tax payout by up to a year, and we removed
  mid-month rounding on before tax and after tax payout dates. For
  example, a payout that would have been on October 28 will now be
  reported as October not November.
- Fixed an issue on the Comparison tab where users could get a ‘Divide
  by zero’ error. A folder result could result in the error in Oracle or
  SQL Server databases.
- Fixed an issue on the Comparison tab where users could get a
  ‘unrecognized token’ error. The error could occur for SQLite databases
  when a user selected a Custom product from the Production comparison
  and no wells in the selection had product results.
- Fixed an issue with the 'Show liquids details' option (new in 2016).
  The option was missing in the Batch Manager's Preview option when
  viewing a Change Record Summary report.
- Fixed an issue with the Change Record Summary report. The Units label
  display (e.g. Mbbl and MBOE) was not changing to SI (but the values
  were). The Total Liquids and Equivalent sections unit just showed
  'Mbbl' and 'MBOE' respectively for SI.
- Fixed an issue where reports were not printing properly on A4 paper
  and spanning 2 pages.
- Fixed Custom Reporter to save reports with accented characters.

### Tools and UI

- Fixed an issue in Spreadsheet Import where UWI was not recognized as a
  valid entity. The import now queries based on unique ID to avoid
  problems with case sensitivity and variations in event sequence.
- Fixed an issue in Spreadsheet Import \&gt; Declines card. If the second
  segment used a linked Start Date and specified an End Date the import
  failed with the message: Import error: End date must be greater than
  or equal to the start date.
- Fixed an issue where the Spreadsheet Import \&gt; Interests card imported
  an interest with BPO having a Payout Reversion (no \$ value) and
  adding an APO 1 column.
- Fixed a Filter issue so that the Type Well Link item now considers the
  plan associated with a link to the type well.
- Fixed an issue where the Edit Custom Fields button on Data Views was
  active for a user who does not have edit rights for Custom Fields.
- Fixed an issue where a price deck linked to jurisdiction could be
  deleted. There was no warning to the user (admin) that it was used in
  a scenario or jurisdiction.
- Fixed an issue in Data Views grids where the expected number of rows
  was not returned in a multi-row selection. This could happen for users
  using a Windows display setting not equal to 100% DPI.
- Fixed an issue in Data Views grids where date range results were not
  working as expected. The 'selection state' of the Date dimension
  object was not copied when moving a row to a column or vice versa.
  This meant that explicitly set date ranges were misinterpreted and so
  no date filter was applied.
- Fixed an issue in 2016 where tabs in Value Navigator could be removed.
  If a user used a mouse wheel button to click on any of the top tabs it
  would disappear until the project was closed.
- Fixed an issue in the Comparison \&gt; Economic tab where the list of
  products was not immediately refreshed when a new product was added.
  The database previously had to be closed and re-opened for the
  addition to be visible.
- Fixed an issue where ratios for secondary products might not be
  included in an archive. This could occur if a gas well had an oil
  decline with a GOR or WOR ratio or similarly an oil well had a gas
  decline with OGR or WGR ratio. Ratio products were not properly added
  to archive system lists in these cases.
- Fixed an issue where an XML import failed in Oracle databases. This
  could occur if the source data contained a Bulk Well Schedule and the
  BWS source well was not included. We now include the source well in
  the import with the BWS even if it is not specifically included in the
  entity list.

### Error Reports

- Fixed an issue where the Predictions \| Data tab would cause an error
  ‘Object reference not set to an instance of an object’ when a graph
  comment was added via the Comments tab.
- Fixed an issue where users could get a ‘entity was not locked and
  could not be saved’ error. For some operations if an entity lock was
  not acquired for one user then the lock was cleared for all users.
- Fixed an issue where users could get a ‘User must be logged in’ error.
  In some instances, the current entity was not cleared on disconnect.
- Fixed an issue where users could get a ‘Invalid path when loading
  config’ error. Added fall-back logic for the default documents folder
  where the operating system returned either a null or unrooted path.
- Fixed an issue where users could get a ‘eni.framework.logger threw an
  exception’ error. Now detect a log file location that does not exist
  or is not writeable.
- Fixed an issue where users could get a ‘Primary series could not be
  resolved’ error when using Ctrl-Click (Refit from point) on a Daily
  data graph. We now detect on mouse click if the product can be fit.
- Fixed a reported crash when graph scaling factors were set to an
  extreme value. Users could get a ‘Value was either too large or too
  small for an Int32’ error.
- Fixed an issue where users could get a ‘An error occurred while
  loading the entity’ error after an upgrade. The upgrade failed because
  of an invalid Custom Field value.
- Fixed an issue where
  Value
  Navigator crashed on an out of memory exception on the Reports
  tab. We now handle the exception and return a message to users.
- Fixed a rollup issue where users could get a ‘\[user\] does not have
  permission to delete an entity that has been posted’ error. This could
  occur when updating a temporary rollup if the rollup existed before
  the database was posted, and the user did not have Write to Accepted
  permission.
- Fixed an issue where users could get a ‘An entry with the same key
  already exists’ error. This occurred if users have Windows short date
  formats with no days or months.
- Fixed an issue where users could get a ‘Stack overflow’ error when
  calculating economic results. This could occur where a negative wedge
  resulted in a recursive loop.
